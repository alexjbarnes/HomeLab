- v2 gotchas (from upstream client/core/rs/src/entities/server.rs @v2.1.0): Server `address` empty means Core expects Periphery->Core (outbound), so an existing inbound Server must have its Address cleared to switch to outbound. Reattaching an existing Server needs a privileged onboarding key and PERIPHERY_CONNECT_AS equal to the Server name. Mismatched Periphery keys are stored as attempted_public_key for later acceptance. Order matters: persist Core keys (keys:/config/keys) BEFORE onboarding a Periphery that pins core.pub, or the next Core recreate breaks it. <!-- id:f1c9 -->
- Komodo v2 changed the Core<->Periphery connection (noise handshake + PKI keys, optional outbound Periphery). Upgrade guide (upstream docsite/docs/releases/v2.0.0.md) requires BOTH Core and every Periphery on v2, plus `init: true` and a `keys:/config/keys` volume on Core and Periphery containers. Commit 935a0ec lacked both in VMs/Docker/Komodo/komodo/compose.yaml. They were added in the working tree on 2026-09-24 (uncommitted at the time). <!-- id:fbdf -->
